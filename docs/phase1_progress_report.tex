\section{Summary}

Phase 1 establishes the first complete upload-to-review loop for the Bank
Statement Scanner. Users can upload a statement from the dashboard, select a
bank, send the file to the FastAPI backend, persist statement metadata in the
database, parse transaction rows, poll status by unique statement ID, and view
extracted transactions in the dashboard.

The Phase 1 code is pushed to the GitHub branch:
\begin{quote}
\texttt{phase1-upload-ui}
\end{quote}

A draft pull request was created:
\begin{quote}
\url{https://github.com/RathlavathArun/Bank_statement_scanner/pull/1}
\end{quote}

\begin{itemize}[leftmargin=*]

\section{Known Notes}

\begin{itemize}[leftmargin=*]
  \item The current parser is sufficient for Phase 1, but production-grade PDF parsing will need more bank-specific hardening.
  \item Uploads are still saved locally, not in S3 or MinIO.
  \item A default firm/client is created for unauthenticated statement uploads. Later phases should connect uploads to the authenticated user's real firm/client context.
  \item Local files under \texttt{apps/api/uploads} and \texttt{apps/api/bank\_statements.db} are intentionally ignored.
  \item A local sample file named \texttt{sample-hdfc-statement.csv} exists for manual testing. It was created after the draft PR and is not included in PR \#1 unless committed separately.
\end{itemize}

\section{Suggested Next Phase}

\begin{enumerate}[leftmargin=*]
  \item Connect statement uploads to authenticated user, firm, and client records.
  \item Add a statement list endpoint so the dashboard can load persisted statements after refresh.
  \item Improve PDF parsing accuracy for real HDFC, ICICI, and SBI samples.
  \item Add XLS/XLSX parsing.
  \item Move parser execution to a background worker.
  \item Store uploaded files in S3/MinIO instead of local disk.
  \item Add review/edit workflows for extracted transactions.
\end{enumerate}
